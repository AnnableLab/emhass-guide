### Configuration

Unfortunately, EMHASS has a long and confusing configuration page, many of which are not actually required.

Thankfully, we can completely ignore the EMHASS configuration page, so just leave it as default. We will be overriding
the values we care about later when running EMHASS. If you have already configured things and are having any trouble,
try resetting them to the defaults.

### API authentication (EMHASS 0.18.10+)

Newer EMHASS versions require a bearer token for REST API requests. EMHASS automatically generates a token when
`emhass_api_token` is left blank in the add-on configuration. Open the **EMHASS Web UI** and select **API token** to
copy the generated token.

Alternatively, to create your own secure token, run this command in the Home Assistant Terminal:

```bash
openssl rand -hex 32
```

Paste its output into `emhass_api_token` under **Settings → Add-ons → EMHASS → Configuration** and restart the EMHASS
add-on.

In Home Assistant's `/config/secrets.yaml`, add the following, using either your automatically generated token or your
manually created token:

```yaml
emhass_bearer: "Bearer YOUR_EMHASS_API_TOKEN"
```

The REST commands above use `Authorization: !secret emhass_bearer`. Include `Bearer` followed by one space and the token
in the secret value. The EMHASS API token is different from your Home Assistant long-lived access token.

After saving `secrets.yaml` and the REST commands, restart Home Assistant. Run your EMHASS optimisation script to test
it. An HTTP `401 Unauthorized` error generally indicates a missing or incorrect bearer token.
